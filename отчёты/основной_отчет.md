# Отчёт по интерфейсу и состоянию проекта SMP Multiverse  
**Дата актуальности:** 21 февраля 2026

> **Обновлено:** От 16.02 — От 17.02: исправлены конфликты Git, восстановлен функционал сайдбара

## 1. Общее описание проекта (полный контекст)

**SMP Multiverse** — веб-сайт, который должен стать главным хабом для поиска, навигации и взаимодействия с SMP-серверами Minecraft.

**Проблема, которую решает проект:**

- Полное отсутствие удобной централизации SMP-серверов  
- Основные площадки обсуждения — Telegram-каналы «SMP Confession» и «SMP Trigger»  
- Способы поиска серверов сейчас:  
  • переход по рекламе наборов  
  • пост «ищу сервер с такими-то условиями»  
  • личные сообщения от админов/игроков  
- Итог: хаос, нет фильтров, нет нормального обзора, нет атмосферы и лора

**Цель сайта**  
Создать красивый, атмосферный, удобный инструмент, которым приятно пользоваться **и игрокам, и администраторам серверов**.

## 2. Ключевые принципы и философия

- Сайт должен быть **атмосферным** и интересным сам по себе  
  (маскот, анимации, звуки, кастомизация, отсылки к SMP-культуре)  
- Админам должно быть **выгодно и приятно** добавлять сервер  
  (широкие возможности персонализации карточек, иконок, музыки, свечения)  
- Игрокам должно быть **удобно** находить подходящий сервер  
  (мощная система фильтров, теги-редфлаги, возрастной рейтинг, заявки на сайте)  
- Визуальная концепция — **карта мультивселенной в межпространстве**  
  (вдохновение: 2 сезон «Adventure Time: Fionna and Cake»)  
- Сайт позиционируется как **каноническое сюжетное дополнение** к лору SMP  
  (миры-сервера связаны между собой, персонажи могут путешествовать)

## 3. Основные фичи (желаемый полный функционал)

### Для игроков
- Мощный поиск + фильтры  
  (настроение, сеттинг, сложность, лицензия, хардкор/3 жизни, время суток, биомы и др.)  
- Фильтрация по **редфлагам** / триггерам  
  (насилие, секс, ЛГБТ, токсичность, другие — админ сам проставляет теги)  
- Возрастной рейтинг сервера (12+, 16+, 18+) — отображается явно  
- Подача заявки **прямо на сайте** (встроенная форма или iframe)  
- Профиль игрока:  
  • аватар  
  • ник(и) Minecraft  
  • скины (пока 2D, несколько слотов)  
  • био (форматирование, эмодзи, гифки, картинки)  
  • отзывы (на игроков и на сервера)  
- Избранное (серверы + игроки) — доступ через маскота

### Для админов серверов
- Добавление сервера через подробную анкету (~30 вопросов)  
- Автоматическое размещение на карте  
- Персонализация карточки сервера:  
  • рамка карточки  
  • рамка иконки  
  • цвет свечения на карте  
  • 5-секундный аудио-отрывок при открытии карточки  
- Указание статуса набора (открыт / закрыт / пре-регистрация)  
- Указание редфлагов, тем, возрастного рейтинга  
- В будущем — интеграция платежей за проходку (Stripe / аналоги)

### Карта и лор
- 2D-карта межпространства (стиль — космическая карта)  
- Серверы = точки / иконки (при зуме превращаются в кастомные)  
- Авторазмещение по анкете:  
  • похожие серверы → ближе  
  • противоположные → дальше  
  • кнопка «максимальная противоположность»  
- Случайные «пути между мирами» (как порталы в Adventure Time)  
- При приближении — раскрытие кастомных иконок

## 4. Интерфейс (текущее видение)

**Цветовая схема**  
- Основной фон: тёмный космос (#0a0015 → #000814) + звёзды  
- Акценты: тусклый розовый (#ff69b4), фиолетовый (#9370db / #c3b1e1), неон  
- Свечение, градиенты, лёгкий glow

**Левый сайдбар**  
- Меню (поиск, мои сервера, профиль)  
- Последний сервер / текущий сервер игрока  
- Космическая погода (шутка, меняется раз в сутки)  
- Инфо о выбранном сервере (collapsible)  
- В будущем — блок рекламы

**Правая верхняя часть**  
- Маскот (пока 👻 → должен быть GIF: призрак-носок с шевелюрой, очками, розовым эктоплазменным хвостом)  
- Клик по маскоту → дропдаун: профиль, мои сервера, настройки, выход, смена аватарки маскота  
- Уведомления (колокольчик + временные toast 10 сек)  
- Dev-меню (гаечный ключ — генерация тестовых серверов и т.д.)  
- Регион (как на YouTube)

**Карточка сервера**  
- Фото-слайдер сверху  
- Лого поверх фото  
- Рейтинг (звёзды)  
- Краткое описание  
- Статус набора  
- Возрастной рейтинг (правый верхний угол)  
- Кнопка «Перейти на страницу сервера» (полный экран)  
- Сердечко (избранное)  
- Отзывы

### 6.0.1. Интеграция пользовательских серверов с картой
- Сохранённые серверы теперь считываются из `localStorage` (`smp.multiverse.servers`) при загрузке `index.html`.
- Если у сервера нет координат, они генерируются автоматически (временный алгоритм), чтобы сервер сразу отображался на карте.
- Тестовые серверы остаются fallback-вариантом только если пользовательских серверов ещё нет.

### 6.0.2. Статус Godot Web и причина ошибки SharedArrayBuffer
- Ошибка
  - `Cross Origin Isolation`
  - `SharedArrayBuffer`
  появляется при запуске Godot Web без правильных HTTP-заголовков.
- Для корректной работы добавлены dev-инструменты запуска COI-сервера:
  - `dev_server.py`
  - `serve-coi.ps1`
- Требуемые заголовки подтверждены:
  - `Cross-Origin-Opener-Policy: same-origin`
  - `Cross-Origin-Embedder-Policy: require-corp`
  - `Cross-Origin-Resource-Policy: cross-origin`

### 6.0.3. Плавность переходов и загрузки сцены

## 7. Что требует доработки (текущий backlog)

### 7.1. Частично реализовано (нужно довести)
- Dev-меню: есть рабочий каркас, но часть вкладок и данных остаётся демо.
- Уведомления: пока без полноценного источника событий и истории.

### 7.2. Не реализовано
- Backend отсутствует (нет Node/Django/Firebase в прод-связке).
- Нет авторизации/пользовательских аккаунтов и хранилища данных серверов/отзывов.
- Нет полноценной анкеты добавления сервера и алгоритма автоматического размещения по параметрам.
- Нет готовых страниц карточек серверов с полным циклом (просмотр/редактирование/модерация).

## 8. Правило стабильности космической сцены (обязательно)

- UI-переключения (сайдбар, панели, модалки) не должны перезапускать или пересоздавать состояние сцены.
- Запрещён принудительный `resize`/re-init сцены по `transitionend` интерфейсных элементов.
- На resize меняется размер canvas и масштаб существующих объектов; пересоздание делается только при первом запуске.
- Орбитальная динамика и мерцание рассчитываются от общего детерминированного времени (фиксированная эпоха + синхронизированное время).
- Клиент выполняет синхронизацию часов по HTTP `Date` заголовку (HEAD к локальному ресурсу), вычисляет offset и периодически ресинхронизируется.
- При недоступности заголовка используется безопасный fallback на локальные часы без остановки сцены.
- Компенсация центра по X вычисляется от фактического `transform` сайдбара, поэтому переходы остаются визуально ровными и синхронными.
- Это сохраняет непрерывность движения и делает поведение телесных объектов максимально единым у пользователей.
